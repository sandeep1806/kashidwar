# काशी द्वार — Kashi Dwar

> **kashidwar.com** — a world-class spiritual guide to Varanasi: ghats, mandirs, Banarasi khana, festivals and yatra tips. Premium cinematic design with Banarasi soul, SEO-first, AdSense-ready.

Built with **Astro** (static output) + **Tailwind CSS v4**. No backend, no database, ~16KB total JS. See [CLAUDE.md](CLAUDE.md) for the project vision, phase roadmap and design/SEO rules; [CREDITS.md](CREDITS.md) for the image log.

## Local development

```bash
npm install
npm run dev       # http://localhost:4321
npm run build     # outputs to dist/
npm run preview   # serve the production build locally
```

## Deploying to Cloudflare Pages

1. Push this directory to a Git repository (GitHub/GitLab).
2. In the Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git**, pick the repo.
3. Build settings:
   - **Framework preset:** Astro
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - (If the site lives in a subdirectory of the repo, set **Root directory** to `kashidwar`.)
4. Deploy. Every push to the production branch redeploys automatically; other branches get preview URLs.

### Custom domain: kashidwar.com

1. Pages project → **Custom domains → Set up a custom domain** → `kashidwar.com`.
2. If the domain's DNS is on Cloudflare (recommended), the CNAME is added automatically; otherwise point a CNAME at `<project>.pages.dev`.
3. Add `www.kashidwar.com` as a second custom domain, then use a **Bulk Redirect** (or a redirect rule) to send `www` → apex with 301.

### kashidwar.in → kashidwar.com (301, avoids duplicate content)

Serving the same site on two domains splits your SEO authority and risks duplicate-content filtering. Redirect the .in domain entirely:

1. Add `kashidwar.in` as a zone in Cloudflare (free plan is fine) and point its nameservers at Cloudflare.
2. Create a proxied DNS record for the apex (e.g. `A 192.0.2.1` — a dummy, since the redirect rule intercepts it; or use `AAAA 100::`).
3. **Rules → Redirect Rules → Create rule:**
   - When: Hostname contains `kashidwar.in`
   - Then: **Dynamic** redirect to `concat("https://kashidwar.com", http.request.uri.path)`, status **301**, preserve query string.
4. Repeat for `www.kashidwar.in` (covered automatically if the rule matches the whole zone).
5. Verify: `curl -I https://kashidwar.in/ghats/assi` should return `301` with `location: https://kashidwar.com/ghats/assi`.

## Google Search Console

1. Open [Search Console](https://search.google.com/search-console) → **Add property** → Domain property `kashidwar.com`.
2. Verify via the DNS TXT record Google provides (Cloudflare DNS → add TXT → wait a few minutes → Verify).
3. **Sitemaps** → submit `https://kashidwar.com/sitemap-index.xml` (generated by `@astrojs/sitemap` on every build; also declared in `public/robots.txt`).
4. Request indexing for the homepage and a few key pages (URL Inspection → Request indexing) to speed up first crawl.
5. After a week, check **Pages** (indexing status) and **Enhancements** (FAQ / breadcrumb rich results should appear, since the site ships FAQPage, BreadcrumbList, TouristAttraction and Event JSON-LD).

## AdSense pre-application checklist

Apply only when ALL of these are true — premature applications get rejected and slow down re-review:

- [x] **15–20+ quality pages** of original content, 400+ words each (this build ships 28 content pages — ghats 12, mandirs 6, festivals 4, khana, tips, about, contact, privacy, home)
- [x] **Privacy policy** with cookies/advertising disclosure (`/privacy`)
- [x] **About** and **Contact** pages (AdSense reviewers check for these)
- [x] Original images with documented licenses (see CREDITS.md — Unsplash, commercial-safe)
- [x] Clean navigation, no broken links, mobile-friendly, fast (Core Web Vitals)
- [ ] **2–3 months of organic traffic** — AdSense favours sites with real visitors; build Search Console history first
- [ ] Domain email (e.g. namaste@kashidwar.com) configured and working
- [ ] Site live on the final domain (not a `.pages.dev` preview) for the whole review period
- [ ] EU consent mode plan (Google CMP or equivalent) if targeting EEA/UK traffic

When approved: paste the AdSense snippet into the `<!-- AD SLOT -->` placeholders rendered by `src/components/AdSlot.astro` (positions: `header-below`, `in-content`, `sidebar`). The slots already reserve space via CSS `aspect-ratio`, so ads cause **zero layout shift**. Keep content dominant — never more ad than article in a viewport (AdSense policy and good taste agree).

## Performance notes

- All animation is CSS transform/opacity + a single ~4KB vanilla JS file; `prefers-reduced-motion` falls back to static rendering everywhere.
- Images are pre-sized WebP with explicit `width`/`height` (no CLS) and lazy-load below the fold; detail-page heroes use `fetchpriority="high"`.
- Note: the repo pins `vite@^7` as a devDependency so `@tailwindcss/vite` resolves against Astro 6's Vite rather than pulling its own Vite 8 (build breaks otherwise).
